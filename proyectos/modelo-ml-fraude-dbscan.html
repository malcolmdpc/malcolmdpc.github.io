Proyecto 10 · Machine Learning

Modelo Machine Learning · Fraude con DBSCAN

✅ publicado

Análisis de transacciones con tarjetas de crédito para reconocer patrones de comportamiento y detectar operaciones atípicas. El proyecto utiliza DBSCAN, un algoritmo de aprendizaje no supervisado que forma grupos según la densidad de los registros e identifica transacciones aisladas.

CONTEXTO Y OBJETIVO

El proyecto trabaja con registros de operaciones realizadas con tarjetas de crédito y analiza las características de cada transacción. A partir de esa información, identifica comportamientos habituales, analiza cómo se agrupan operaciones parecidas y detecta casos que se diferencian del resto.

Para estudiar esas diferencias se utiliza DBSCAN, un método de aprendizaje automático que agrupa operaciones según la similitud entre sus características. El procedimiento reconoce concentraciones de transacciones parecidas y destaca otras que quedan aisladas.

El análisis busca comprender esos comportamientos y identificar operaciones atípicas para revisarlas con mayor detalle. Cada caso puede evaluarse después con más información sobre el contexto de la transacción para evaluar si requiere una investigación específica.

MODELO Y ANÁLISIS

PREPARACIÓN DE LAS OPERACIONES

El trabajo utiliza las variables registradas en las transacciones, como el importe y otras características de cada operación. Se revisa la calidad de los datos y se preparan las variables que permiten comparar los registros bajo criterios consistentes.

La comparación se basa en cuánto se parecen las operaciones. Para considerar variables expresadas en rangos numéricos diferentes, el proyecto ajusta sus escalas antes de identificar los grupos.

IDENTIFICACIÓN DE GRUPOS CON DBSCAN

DBSCAN identifica áreas donde se concentran operaciones con características semejantes y forma grupos a partir de esas concentraciones. Para reconocerlas, considera qué registros están suficientemente cerca entre sí y cuántas operaciones similares hay alrededor de cada una. Así, el agrupamiento surge de la distribución observada en los datos.

El resultado permite distinguir tres situaciones:

  • Operaciones de núcleo: están rodeadas de varios registros parecidos y ayudan a formar los grupos.
  • Operaciones de borde: están cerca de un grupo de transacciones similares.
  • Operaciones aisladas: quedan fuera de los grupos identificados y reciben la etiqueta -1.

ANÁLISIS DE LAS OPERACIONES ATÍPICAS

Los gráficos muestran cómo se distribuyen las operaciones y qué características comparten los registros de cada grupo. También permiten comparar esos grupos con los casos aislados y ayudan a reconocer comportamientos que merecen una revisión más detallada.

La etiqueta -1 señala una operación atípica según los criterios utilizados en el análisis. Su importe y sus demás características pueden estudiarse junto con información adicional para evaluar si se trata de una compra poco habitual o de una situación que requiere investigación.

ENTREGA Y APRENDIZAJE

El proyecto incluye un notebook en Python con la preparación de los datos, el agrupamiento mediante DBSCAN y los gráficos para explorar los resultados. Ese material permite analizar los grupos de operaciones y seleccionar operaciones atípicas para una revisión posterior.

Cuando se incorporan nuevas transacciones, el procedimiento puede repetirse para observar cómo cambian los grupos y qué casos aparecen como atípicos en los datos actualizados. Mantener los mismos criterios de preparación facilita la comparación entre ambos análisis.
