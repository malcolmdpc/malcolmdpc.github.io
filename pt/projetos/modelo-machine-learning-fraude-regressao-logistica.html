Projeto 09 · Machine Learning

Modelo Machine Learning · Fraude com Regressão Logística

✅ publicado

Análise de transações com cartões de crédito para estimar a probabilidade de fraude através de regressão logística. O projeto utiliza informação de operações já classificadas para treinar um modelo que identifica sinais associados ao risco e permite analisar as suas previsões.

CONTEXTO E OBJETIVO

O projeto utiliza registos de operações com cartões de crédito para estudar que características aparecem com maior frequência nas operações associadas a fraude. Cada transação contém dados que descrevem a operação e uma classificação que indica se foi registada como legítima ou fraudulenta. Esta informação permite treinar um modelo com exemplos conhecidos e aplicá-lo depois a outras transações.

O objetivo é estimar a probabilidade de fraude de cada operação e reconhecer que variáveis contribuem para essa estimativa. A regressão logística permite abordar ambas as tarefas: classifica as transações e permite interpretar a relação entre as suas características e o resultado previsto.

MODELO E AVALIAÇÃO

PREPARAÇÃO DOS DADOS

Primeiro são revistas as variáveis do conjunto de transações e organizada a informação utilizada pelo modelo. A preparação inclui a limpeza dos dados, a preparação das variáveis e o equilíbrio das classes, um aspeto importante quando os casos de fraude são muito menos frequentes do que as compras legítimas.

Esta preparação deixa os dados prontos para treinar e avaliar o modelo. As variáveis selecionadas descrevem cada operação, enquanto a classificação conhecida de fraude funciona como referência para que o modelo aprenda a distinguir os dois tipos de casos.

CLASSIFICAÇÃO COM REGRESSÃO LOGÍSTICA

A regressão logística combina as características de cada transação e estima uma probabilidade de fraude entre 0 e 1. Cada variável contribui para o cálculo através de um coeficiente ajustado durante o treino. A função logística converte essa combinação numa probabilidade para cada operação.

PROBABILIDADE ESTIMADA DE FRAUDE
p(x)=\frac{1}{1+e^{-(\beta_0+\sum_{j=1}^{k}\beta_jx_j)}}

p(x) é a probabilidade estimada de fraude. Os x representam características da transação; os coeficientes beta refletem o contributo aprendido de cada variável.

Os coeficientes permitem analisar a relação de cada característica com a probabilidade estimada, tendo em conta as restantes variáveis. Assim, podem reconhecer-se sinais associados a um risco maior ou menor nas transações analisadas.

AVALIAÇÃO DAS PREVISÕES

A avaliação compara as previsões com a classificação conhecida das operações. Para decidir que transações são assinaladas como possíveis fraudes, a probabilidade estimada é comparada com um limiar de decisão. Esse valor influencia quantas fraudes são detetadas e quantas compras legítimas geram alertas para revisão.

LIMIAR PARA CLASSIFICAR TRANSAÇÕES
\hat{y}=\begin{cases}1&\text{si }p(x)\geq t\\0&\text{si }p(x)<t\end{cases}

Nesta regra geral, 1 identifica um alerta de possível fraude e 0 uma operação classificada como legítima. t é o limiar de decisão, cujo valor específico pode ser escolhido segundo o critério de avaliação.

O projeto implementa o processo de modelação em SPSS Modeler e inclui outra implementação em Python. As métricas e os gráficos de avaliação permitem avaliar o desempenho do modelo e analisar os sinais associados à fraude com as duas ferramentas.

ENTREGA E APRENDIZAGEM

O trabalho apresenta um modelo supervisionado de regressão logística aplicado a operações com cartões de crédito, juntamente com a preparação das variáveis, as previsões e os resultados da avaliação. A combinação de SPSS Modeler e Python permite acompanhar o procedimento e analisar o contributo das variáveis para a classificação.

Ao incorporar novas transações com as mesmas variáveis, o modelo pode gerar estimativas a comparar depois com os casos confirmados. Essa comparação permite verificar se mantém a capacidade de deteção e decidir quando atualizar o treino.
